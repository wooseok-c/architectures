## 0. 한 문장

**GRU = 요약 벡터 `h`를, 단어 하나씩 받으며, 문(gate) 2개로 "얼마나 유지 / 얼마나 갈아탈지" 조절하며 갱신하는 것.**

---

## 1. 큰 그림 (context vector)

- 문장을 단어 단위로 읽으며 `h`를 계속 갱신.
- 문장 끝까지 읽으면 → 마지막 `h` = **문장 전체의 요약 `c` (context vector)**.
- 번역기: [인코더] 한국어 → 요약 `c` → [디코더] 영어 생성.
- 그냥 RNN의 문제: `h`를 매 단어 **통째로 새로 씀** → 긴 문장에서 앞부분이 흐려짐(gradient 소멸).

---

## 2. 벡터 vs 행렬 (오늘의 핵심!)

| | 뜻 | 예 | 역할 |
|---|---|---|---|
| **벡터** | 숫자 한 줄 (1차원) | `x`(단어), `h`(요약), `r`(게이트) | **데이터** |
| **행렬** | 숫자 격자 (2차원) | `W_r`, `U_r` ... | **변환기/규칙** |

- **규칙: 행렬 × 벡터 = 벡터.** (기계가 물건을 먹어서 새 물건을 뱉는다.)
- `(행, 열)` 순서. `(6, 5)` = **6행 5열**.
  - **열 = 받는 쪽** = 곱하는 벡터 길이 (입력이면 `I`, 기억이면 `H`)
  - **행 = 내는 쪽** = 항상 `H` (게이트가 hidden 길이라서)

---

## 3. weight sharing (신기했던 부분)

- 모든 단어 = **같은 크기 벡터** `I`개 (embedding). "나는", "학교에" 다 5개 숫자.
  → 그래서 `W_r`은 항상 `(H, I)` 고정. **단어/문장에 따라 안 변함.**
- 문장이 길면 → **같은 행렬을 더 여러 번 반복**할 뿐 (weight sharing).
- `W_r` 크기는 오직 `I`(임베딩 차원), `H`(hidden 차원)로만 정해짐.

> ❌ "행 = 단어"  /  ✅ "행 = hidden 유닛, 열 = 입력 성분, 단어 = 시간 스텝"

---

## 4. GRU 수식 = 질문 3개 + 섞기 1개

```
① reset gate:  r     = σ(W_r x + U_r h)        "과거를 볼까?"      (0~1)
② update gate: z     = σ(W_z x + U_z h)        "옛것을 지킬까?"    (0~1)
③ candidate:   n     = tanh(W x + U(r ⊙ h))    "새로 쓸 내용은?"   (초안)
④ blend:       h_new = (1−z) ⊙ n + z ⊙ h       "유지 vs 교체"
```

- `σ` → 0~1 손잡이, `tanh` → 내용(-1~1), `⊙` → 성분별 곱(`*`).
- **③에서 `r`은 `h`쪽에만 곱함!** (`x`쪽 아님)
- **④의 `z ⊙ h` 가 과거를 살리는 gradient highway.**
  - `z≈1` → 옛 요약 유지(장기 기억) / `z≈0` → 초안으로 갈아탐.

---

## 5. weight 행렬은 총 6개 (+ bias)

| 입력쪽 `(H, I)` | 기억쪽 `(H, H)` |
|---|---|
| `W_r`, `W_z`, `W` | `U_r`, `U_z`, `U` |

- 코드에선 속도 위해 **쌓아둠**:
  - `weight_ih (3H, I)` = `[W_r; W_z; W]` (입력쪽 3개)
  - `weight_hh (3H, H)` = `[U_r; U_z; U]` (기억쪽 3개)
  - `ih` = input→hidden, `hh` = hidden→hidden. **뒤 글자 h = 내는 쪽 항상 H.**

## 7. LSTM (그다음, `lstm.py`)

- **게이트 3개** `i, f, o` + **후보 1개** `g` (GRU는 게이트 2 + 후보 1).
- 진짜 차이: **기억 통로 `c`를 출력 `h`와 분리.** (GRU는 `h` 하나로 통합)

```
i = σ(·)  input   "새 내용 받을까?"
f = σ(·)  forget  "옛 기억 유지?"      (GRU z 역할)
g = tanh(·)       "새 후보 내용"        (GRU n 역할)
o = σ(·)  output  "기억 중 얼마 내보낼까?"  (GRU엔 없음)
c_new = f ⊙ c + i ⊙ g       ← f⊙c 가 기억 하이웨이
h_new = o ⊙ tanh(c_new)     ← 새 c 를 씀!
```

- `f`↔`z`, `i`↔`(1−z)` 비슷하지만 **LSTM은 f/i 독립**(GRU는 묶임).

---

## 8. GRU vs LSTM 한 줄

- **GRU**: 파라미터 ~25%↓, 가볍고 빠름. 상태 1개(`h`).
- **LSTM**: 더 세밀한 제어(독립 f/i, 출력 게이트). 상태 2개(`c`, `h`).
- 성능은 **대체로 비슷** → GRU는 "안 나눠도 충분하더라"는 단순화 버전.
- 역사: LSTM(1997)이 먼저, GRU(2014)가 간소화. 결국 둘 다 → **Attention/Transformer**로.
